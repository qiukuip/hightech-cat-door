## 1. 设计目标

- 在 ESP32-S3-CAM 与 N100 mini-PC 之间传输**指令**（短帧，< 10 字节）和**图像**（长帧，~30–60 KB JPEG）。
- 局域网单端口复用（默认 `:1234`），同一 TCP 端口同时服务门外和门内两侧节点；身份在连接建立后通过一帧 `0x8` 帧声明。
- 帧边界清晰，无歧义；解析逻辑简单（无状态机，仅按字节序读）。
- 错误可恢复：单帧失败不应导致连接断开（除非出现 magic 错或长度异常）。


## 2. 帧结构

固定长度头 + 变长体：

| 字段 | 长度（字节） | 说明 |
|------|--------------|------|
| 魔数（magic）  | 1 | 固定为 `0xAA` |
| 消息类型（type）| 1 | 标识消息用途（见 §3） |
| 消息长度（total）| 2 | **整个消息**的总长度（小端序 LE），含本 4 字节头 |
| 数据体（body） | 可变 | 业务数据，二进制格式；可为空（length=4） |

约束：

- `total ∈ [4, 65535]`，body 上限 **65531 字节**。ESP32 端若 JPEG 超过此阈值会直接丢弃。
- magic 不匹配 → 整帧视为错误，关闭连接。
- `total < 4` 或 `total > 65535` → 关闭连接。

字节序：除 magic/type 外，所有数值字段均使用 **小端序（LE）**。

最小帧（心跳）：

```
[AA] [00] [04 00]            // type=0x0, total=4, body 空
```

含 body 的帧：

```
[AA] [10] [bodyLen+4 LE 2B] [body bytes...]
```


## 3. 消息类型（type）完整规范

| type | 名称 | 方向 | body 长度 | body 语义 |
|------|------|------|-----------|-----------|
| `0x0` | 心跳 | 双向 | 0 | 用于保活；服务端读空闲超时 60s 后会断连重置。 |
| `0x1` | 上传图片并识别 | ESP32 → server | 变长（≤65531） | JPEG 字节流；服务端跑 YOLO 并返回 `0x2`。 |
| `0x2` | 图片识别结果 | server → ESP32 | 1 字节 | `0x00`=not-cat，`0x01`=my-cat。 |
| `0x3` | 下发图片采集指令 | server → ESP32 | 0 | 预留：让指定 ESP32 拍一帧 JPEG 通过 `0x4` 上报。**当前未在流程中使用**。 |
| `0x4` | 采集图片并存储到指定位置 | ESP32 → server | 变长 | JPEG 字节流；与 `0x3` 配对。**当前未在流程中使用**。 |
| `0x5` | 人工开门 / 自动开门 | server → 门内 ESP32 | 0 | 触发门内舵机开锁动作；门内执行后必须上发 `0x7{opening}` → `0x7{open}`。 |
| `0x6` | 人工关门 / 自动关门 | server → 门内 ESP32 | 0 | 触发门内舵机关锁；门内执行后上发 `0x7{closing}` → `0x7{closed}`。 |
| `0x7` | 报告门开闭状态 | 门内 ESP32 → server | 1 字节 | `0x00`=closed, `0x01`=opening, `0x02`=open, `0x03`=closing, `0x04`=passage。 |
| `0x8` | 设备注册/身份声明 | ESP32 → server（连接后**仅发一次**） | 1 字节 | `0x00`=outdoor（门外），`0x01`=indoor（门内）。服务端忽略重发。 |
| `0x9` | 门内雷达触发开锁（含 JPEG） | 门内 ESP32 → server | 变长（≤65531） | JPEG 字节流，单帧；服务端**跳过 YOLO**，保存 JPEG 后直接开锁，方向=出门。 |
| `0xA` | 门外雷达通过事件 | 门外 ESP32 → server | 0 | 雷达在 `OPEN_CAMERA_DISTANCE_CM` 内时每 200ms 上发一次；服务端按 `expectedPassage==outdoor` 决定是否接受。 |
| `0xF` | 断开连接 | 双向 | 0 | 优雅关闭；服务端收到后会关闭读循环、解除该 peer。 |


## 4. TCP 建接握手

服务端 listen 单一端口（默认 `:1234`），**不**按端口区分身份；身份由客户端首帧声明。

```
ESP32                              Server (Go)
  | --- TCP SYN ------------------> |
  | <-- TCP SYN-ACK --------------- |
  | --- TCP ACK ------------------> |   (此时连接建立)
  | --- [0xAA][0x8][0x05][0x00] --> |   register: role=outdoor
  |                                  |   (5s 内未到 → 关闭连接)
  | --- [0xAA][0x0][0x04][0x00] --> |   (可选) 心跳
  | --- [0xAA][0x1][JPEG...] -----> |   业务帧
  | <-- [0xAA][0x2][0x05][0x01] --- |   YOLO 命中自家猫
  | <-- [0xAA][0x5][0x04][0x00] --- |   (进入流程) 下发开锁
  | ...                              |
```

注意：
- register 帧必须在连接建立后 **5 秒内**到达，否则服务端主动 close。`registerTimeout=5s`（见 `src/server/server.go`）。
- register 之后服务端按 role 分流到 `onOutdoorFrame` / `onIndoorFrame` 两个不同的 handler。
- 客户端断连（TCP FIN）后，服务端的 read loop 退出，peer 被注销，下次连接会替换。


## 5. 状态机：服务端 `doorController`

```
        requestOpen(trigger)
                │
        ┌───────▼────────┐
        │      idle      │◄────── DoorStateClosed (0x7{0x00})
        └───────┬────────┘
                │  send 0x5
        ┌───────▼────────┐
        │    opening     │
        └───────┬────────┘
                │  0x7{0x02}
        ┌───────▼────────┐         ┌─────────────────────────┐
        │      open      │◄────────┤   start 30s hold timer   │
        └──┬───────┬─────┘         └─────────────────────────┘
           │       │
   expectedPassage:
     indoor: 0x7{0x04}
     outdoor: 0xA
           │       │ 30s timer fires
           │       │
        ┌──▼───────▼─────┐
        │    closing      │
        └───────┬─────────┘
                │  0x7{0x00}
                └────► idle
```

`expectedPassage` 在 `requestOpen()` 内根据触发源取反：

| 触发源 | `expectedPassage` | 关门信号 |
|--------|--------------------|----------|
| 门外 `0x1` + YOLO=cat（**进入**） | `indoor`  | 门内 `0x7{passage}` |
| 门内 `0x9`（**出门**）              | `outdoor` | 门外 `0xA`         |

未匹配方向的通过事件被服务端忽略（仅日志），避免同一只猫被错误关门。


## 6. 错误处理

| 场景 | 处理 |
|------|------|
| 收到 magic ≠ `0xAA` | 关闭连接（peer 协议不一致） |
| `total < 4` 或 `total > 65535` | 关闭连接 |
| body 大于读 buffer 上限 | 关闭连接 |
| ESP32 端 JPEG > 65531 字节 | ESP32 端丢弃该帧（不发送），打印 `frame too large` |
| 服务端读空闲 > 60s | 关闭读循环，注销 peer（`readIdleTimeout=60s`） |
| 服务端写失败（peer 已关） | 注销 peer，下一次心跳会失败 |
| YOLO 推理异常 | 返回 `not-cat` 给户外 ESP32，**不开门**（保持安全） |
| `--save-dir` 写盘失败 | 仅日志告警，不影响开门流程 |


## 7. 性能参考

- 帧解析复杂度 O(1)（先读 4 字节头，再按 `total-4` 读 body）。
- 4 字节 header + JPEG body 的总开销 = 4 字节 / 帧；JPEG 一般 30–60 KB。
- 服务端单连接读循环串行处理；如需更高吞吐，应改为 per-peer goroutine + 帧队列（当前实现已为每个连接开 goroutine，但 handler 内为同步调用 detector，**未做并发池**）。
