## 背景

猫经常有出去的习惯，门保持常开不安全，人工开门比较麻烦。


## 系统目标

设计一个自动给自家猫开门的系统，主要功能：

- **身份识别**：门外侧必须经 YOLO 确认是自家猫才开门。
- **方向对称**：门内侧无需识别，雷达检测到猫即开门让猫出去。
- **通过检测**：每次开门后由对侧的雷达确认猫已通过，超时则强制关门。
- **图片留存**：每次猫触发开门的事件（无论是 YOLO 确认还是内侧雷达触发）都把对应的 JPEG 写入服务端磁盘，便于审阅与训练集扩充。
- **远程控制**：留有 APP 下发手动开/关门的扩展位（协议已实现 `0x5`/`0x6`）。


## 系统组件

| 组件 | 数量 | 位置 | 作用 |
|------|------|------|------|
| VL53L1X | 2 | 每侧 1 片（门外 1 + 门内 1） | 雷达感知猫接近 |
| 光敏电阻 | 1 | 门外 | 判断是否启用红外补光灯 |
| 红外补光灯 | 1 | 门外 | 暗光下补光 |
| OV2640 摄像头 | 2 | 每侧各 1 | 门外 4 FPS 抓拍供 YOLO；门内只在雷达首次触发时拍单帧留存 |
| ESP32-S3-CAM | 2 | 每侧各 1 | 分别跑 `esp32out.ino` / `esp32in.ino`，连接 WiFi 上报服务端 |
| 舵机 | 2 | 门内 | 一个下拉门把手，一个推门 |
| N100 mini-PC | 1 | 局域网内 | Ubuntu 24.04，跑 Go TCP 服务 + Python YOLOv8n INT8 推理 |


## 系统工作流程

### 通信链路总览

```
                 ┌──────────────────────┐
                 │   N100 Mini-PC       │
                 │  Go TCP Server       │  ← 状态机：idle/opening/open/closing
                 │  + Python YOLO 推理  │  ← 单进程 stdin/stdout，模型常驻
                 └──────────┬───────────┘
                            │ 单端口 :1234（角色由 0x8 register 帧声明）
              ┌─────────────┴─────────────┐
              │                           │
       ┌──────┴───────┐             ┌─────┴──────┐
       │ esp32out.ino │             │ esp32in.ino│
       │ 门外侧节点   │             │ 门内侧节点 │
       │ 雷达+光敏    │             │ 雷达+舵机   │
       │ 红外补光+相机│             │ + 单帧相机  │
       └──────────────┘             └────────────┘
```

每帧结构：`[0xAA][type][total-length LE 2B][body…]`，body 上限 65531 字节。完整 spec 见 `通信协议设计.md`。

---

### 进入流程（外 → 内）

1. **门外雷达检测**：每 200 ms 读 VL53L1X；`distance ≤ OPEN_CAMERA_DISTANCE_CM`（默认 10 cm）→ 视为有猫。
2. **环境判定**：读光敏电阻（连续 `LIGHT_SAMPLES=8` 次均值）；低于阈值则拉高 `PIN_IR_LIGHT=47` 开启红外补光。
3. **连续抓拍**：`esp_camera_init()` → 按 `CAMERA_FRAME_MS=250`（4 FPS）抓 JPEG → 每帧通过 `0x1` 上报。
4. **服务端识别**：每帧调 `Detector.Detect(jpeg)`；若是自家猫（`0x2{0x01}`），把 JPEG 写入 `<save-dir>/outdoor/`，并 `requestOpen(roleOutdoor)`。
5. **服务端开锁**：`state: idle → opening`；`expectedPassage=indoor`；向门内 ESP32 下发 `0x5`。
6. **门内执行**：舵机 1（把手）→ 60° 下拉；延时 500 ms；舵机 2（推拉门）→ 90°（按现场机械标定）。
7. **状态上报**：门内 ESP32 依次上发 `0x7{0x01}`（opening）→ `0x7{0x02}`（open）。服务端收到 open → `state: opening → open`，启动 30 s 定时器。
8. **通过检测**：猫穿过门缝进入室内 → 门内 2 片雷达之一在 10 cm 内 → 门内 ESP32 上发 `0x7{0x04}`（passage）。`passageReported` 标志去重，只发一次。
9. **服务端过滤**：校验 `expectedPassage==indoor` 才接受，下发 `0x6` 关门；`state: open → closing`。
10. **关门确认**：门内 ESP32 舵机回 0°，上发 `0x7{0x00}`（closed）。服务端 `state: closing → idle`；重置 `expectedPassage`。

---

### 出门流程（内 → 外）

1. **门内雷达检测**：每 200 ms 读 VL53L1X；`distance ≤ INDOOR_OPEN_DISTANCE_CM`（默认 10 cm）→ 视为有猫。
2. **首次触发单帧拍照**：`catSessionActive` 由 `false → true` 的瞬间，`esp_camera_init()` → 抓单帧 JPEG → 通过 `0x9` 上报；拍完立刻 `esp_camera_deinit()`（门内无需连续抓拍）。服务端把 JPEG 写入 `<save-dir>/indoor/`，**跳过 YOLO**，直接 `requestOpen(roleIndoor)`。
3. **服务端开锁**：`state: idle → opening`；`expectedPassage=outdoor`；向门内 ESP32 下发 `0x5`。
4. **门内执行**：与进入流程相同的舵机动作。
5. **状态上报**：门内 ESP32 上发 `0x7{0x02}`（open）。服务端 `state → open`，启动 30 s 定时器。
6. **通过检测**：猫穿过门缝到室外 → 门外雷达触发 → 门外 ESP32 **每 200 ms** 上发一次 `0xA`（passage event，body 为空）。
7. **服务端过滤**：校验 `expectedPassage==outdoor` 才接受，下发 `0x6` 关门。
8. **关门确认**：门内 ESP32 关闭舵机，上发 `0x7{0x00}`。服务端 `state → idle`。

---

### 通过事件的双向过滤（关键）

两侧 ESP32 都会持续上报通过事件：

- 门外 ESP32：雷达每次轮询触发都上发 `0xA`（在猫停留期间约每 200 ms 一次）。
- 门内 ESP32：`0x7{passage}` 只上发一次（`passageReported` 去重）。

服务端 `doorController` 维护 `expectedPassage`：

| 触发方 | `expectedPassage` | 接受 | 忽略 |
|--------|--------------------|------|------|
| 门外 `0x1` + YOLO 命中（进入） | `indoor`  | 门内 `0x7{passage}` | 门外 `0xA`（猫还没进，门外一直有信号） |
| 门内 `0x9`（出门）              | `outdoor` | 门外 `0xA`           | 门内 `0x7{passage}`（猫还没出，室内一直有信号） |

这样同一只猫不会触发对侧的"假通过"导致提前关门；同时也容忍门两侧同时有猫（一只进、一只出）的复杂场景。

---

### 超时保护

服务端进入 `open` 状态后立即启动 30 s 定时器；无论是否有通过事件，超时强制下发 `0x6` 关门，避免门一直开着。

---

### 图片留存（`--save-dir`）

启动参数 `--save-dir=/path/to/snapshots`（空字符串 = 禁用）。每次 cat 事件对应的 JPEG 写入：

- 进入：`{save-dir}/outdoor/YYYYMMDD-HHMMSS.mmm-NNNNNN.jpg`
- 出门：`{save-dir}/indoor/YYYYMMDD-HHMMSS.mmm-NNNNNN.jpg`

服务端自动创建子目录；清理/轮转由调用方负责（当前未内置）。

## 阈值（`.ino` 端可调）

| 常量 | 文件 | 默认 | 用途 |
|------|------|------|------|
| `OPEN_CAMERA_DISTANCE_CM`   | `src/esp32out.ino` | 10 | 门外雷达触发距离；同时控制 `0x1` 抓拍与 `0xA` 通过事件 |
| `INDOOR_OPEN_DISTANCE_CM`   | `src/esp32in.ino`  | 10 | 门内雷达触发距离；同时控制 `0x9` 出门触发与 `0x7{passage}` 通过事件 |

调整方式：修改 `#define` 后重新烧录对应固件。改完务必同步更新本文档。

## 资源及约束

- VL53L1X × 2（每侧 1 片，I2C 默认地址 `0x29`；当前实现未启用 XSHUT 时序，仅单传感器）。
- 光敏 × 1、红外补光灯 × 1（仅门外）。
- OV2640 × 2（每侧 1；门内仅在雷达首次触发时启用）。
- ESP32-S3-CAM × 2（每侧 1）。
- 舵机 × 2（仅门内；扭矩需现场评估，必要时改直线推杆）。
- 协议 body 上限 65531 字节；超过的 JPEG 会被 ESP32 端丢弃。
- N100 CPU 推理 ONNX INT8 YOLOv8n 单帧 < 100 ms。

## 附加说明

- YOLOv8n 已训练好（单类 `my-cat`），INT8 ONNX 已导出（`model-training/best_int8.onnx`）。
- iOS APP 仅自用，不上架。开门/关门日志记录待接入 PostgreSQL。
- **🔴 关门安全（评估报告建议）**：在门缝处增加对射红外或压力感应条，关门遇障碍立即反向开门——**当前实现未含此功能，上线前必须补齐**。
- **🔴 雷达抖动防护**：当前实现是单次轮询判定，评估报告建议 ≥ 2 次连续采样综合判断，避免误触。
- **🔴 光敏防抖**：当前 `isBright()` 用 8 次均值；如出现抖动需改成迟滞比较。
- 协议 spec 见 `docs/通信协议设计.md`；pinout 见 `docs/硬件连线设计.md`；完整工程说明见仓库根 `AGENTS.md`。
